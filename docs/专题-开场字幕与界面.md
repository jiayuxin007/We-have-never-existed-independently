# 专题：开场、字幕与界面层

WebGL 房屋和六道特效之外，还有一整层「普通网页」：标题、经文、台词条、提示、光标、终章按钮、右上角仪表的壳。完全不碰三维的人，日常改体验往往改的是这一层。

相关文件：`app/ui/intro-controller.js`、`snowflake-cursor.js`、`sutra-controller.js`、`subtitle-controller.js`、`house-hint.js`、`crosshair-cursor.js`、`final-quote-controller.js`、`karma-data-panel.js`、`path-resolution-hud.js`、`app/styles/main.css`、`app/index.html` 里的 DOM。

**改字先看这张表**（零基础请直接用 [屏幕上看到什么](./专题-屏幕上看到什么.md)）：

| 画面上的字 | 真正的文件 |
|---|---|
| 开场标题 | `intro-controller.js` 的 `INTRO_TEXT` |
| 金刚经 | `index.html` 的 `sutraQuoteStage` |
| 底部叙事 | `stages.config.js` 的 `text` |
| 受的苦乐舍 | `paths.config.js` 的 `VEDANA_SUBTITLES` |
| 淡提示 | `house-hint.js` |
| 终章大字 | `index.html` 的 `final-quote-text`（分镜表里那份**不显示**） |
| 六道 HUD 两句英文壳 | `path-resolution-hud.js` 的 `show()`（会盖掉 HTML） |

## 1. 页面是叠起来的透明纸

`app/index.html` 里预先写好很多个 `div` / `video` / `audio`，用 CSS `position: fixed` 铺满。导演只负责把某一张纸 `hidden` 打开或关上，很少现场「新建一整页」。

从下到上**不是**单纯「后写的盖住先写的」。实际 `z-index`（调试点击用）：

| 层 | z-index | 点击 |
|---|---|---|
| 星空 video | 0 | 无 |
| 开场 | 1 | 有（点彗星） |
| 金刚经 | 5 | 有（可跳过） |
| 特效层 | 10 | 触点球 / 六道时有 |
| 业力面板 | 15 | **无**（`pointer-events: none`） |
| 进度条 HUD | 25 | 无 |
| 底部台词 | 30 | 无 |
| 终章 | 35 | 按钮出现后有 |
| 六道 HUD | 36 | 无 |
| **房屋** | **45** | 有。透明处能看见下面的字和面板；点和模型会挡住台词 |
| 阻塞层 | 50 | 奇点提示时声纳不挡点（`pointer-events: none`） |
| 淡提示 | 55 | 无 |
| 黑场 dip-fade | 80 | 无（`pointer-events: none`） |
| 十字光标 | 9999 | 无。比黑场高，入黑时十字仍在 |

面板在房屋**下面**，不会抢走六入点击。取那段淡出面板是为了画面干净，不是为了解锁点击。

自定义光标**不是** CSS `cursor: url(...)`。系统箭头被 `cursor: none` 藏掉，`crosshair-cursor.js` 另放一张跟着指针走的 40×40 canvas（断开的十字 + 一层发光）。特效自己听 `mousemove` 不冲突，两边都能收到鼠标。Windows 缩放比大时这 40px 会显得糊，不是模型问题。

## 2. 开场（Stage 0）时间轴

文件 `intro-controller.js`，时间在 `timing.config.js`：

| 时刻 | 行为 |
|---|---|
| 0 | 进入开场层 |
| 约 1s | 标题 *We have never existed independently.* 逐字出现，总长约 2.5s（`introRevealDurationS`），每个字母 delay = 序号/字数×2.5s。`introCharAnimS` **没有人读** |
| 前 2s | `introClickLockMs` 把点击设为无效，用来预取 GLB |
| 约 3s | 雪花层出现（`introSnowflakeDelayMs`）。点中要求雪花对象已创建，所以**最早约 3 秒**才能点中；2 秒锁在彗星出来前就已经过了 |
| 点中雪花后 | 关开场、回调 `main.js`：采集 start、行情 start、BGM play、解锁 Web Audio、导演从第 1 段开始 |

雪花本身 `snowflake-cursor.js`：Canvas 2D。256×256 的径向白光只画一次做成「章」，每帧盖章而不是每帧新建渐变（那样会卡）。拖尾约 120 个位置，每个位置再喷十来个小点。画布按屏幕像素比放大，上限 2 倍，4K 屏不至于把 CPU 画死。运动是简单的速度反弹，撞到边距 30px 的矩形就折返。点的是这颗彗星（或拖尾上约 50px 半径内），不是屏幕任意处。

## 3. 金刚经（Stage 1）

`sutra-controller.js` + `#sutraQuoteStage`。英文四行、中文四行，都带 `sutra-reveal-line`。显现**开始前**会等方正字体（最多约 8 秒，`FONT_WAIT_MS`；超时也继续）。点完雪花后的预热会提前开始等，正常走场往往几乎不等。然后约 8 秒显现（`sutraRevealDurationS`）：每个字的 delay 是「该字在全文中的位置 / 总字数 × 8 秒」，中英两栏各自算。`sutraCharAnimS` **没有人读**。显现后再加约 150ms（`sutraRevealTailMs`）和约 5 秒停（`sutraPauseAfterMs`）。期间点经文层可跳过。

结束发 `sutra:complete`。业力面板听到后才 `show()`。所以仪表不是从打开网页就在，而是经文结束后才出现。

字体三套，都在 `app/styles/main.css` 的 `@font-face`：

- **NITEMARE**（`SiteFont`）：开场标题、底部台词、终章大字。
- **Pixelate**：右上角仪表、进度条百分比、部分 HUD。缺了仪表会变成系统等宽，看起来「面板换气质了」。
- **方正 FZCAOYTJW**：金刚经中文。

`index.html` 对 NITEMARE 做了 preload，对 Pixelate / 方正没有。`file://` 下字体经常失败，字会变成系统衬线，看起来「换字体了其实没换上」。

## 4. 底部台词与操作提示是两套

**台词** `subtitle-controller.js`：读分镜表里的 `subtitles`。真正用到的字段只有 `text`、`atMs`、可选的 `fadeDelayMs`。表里常写的 `durationMs` **字幕控制器不读**，字会一直留到下一句 `atMs` 或整段 `hide()`。到点先去掉 `.active`（CSS 淡出），再等 `fadeDelayMs`（缺省 800ms，`subtitleFadeDelayMs`），才换字并淡入。所以观众看见新句的时刻是 **`atMs + 这段等待`**。房屋各段写了 `fadeDelayMs: 0`，几乎对准 `atMs`。触点球两句、生、老死、六道固定句没写 0，会各晚约 0.8 秒。特效段要等特效 `mount` 完成再开始按 `atMs` 计时，否则会出现「字出来了、球还没有」。

受那一段表里虽有一句默认乐受，导演会换成三句里的一句，见业力专题的 vedana。

**提示** `house-hint.js`：闪烁周期写在 `app/styles/main.css` 的 `hintPulse 2.4s`，脚本只听 `animationiteration` 换句。`timing.config.js` 里的 `houseHintCycleMs` **没有人读**，改它无效。每句默认连闪两轮再换下一句。识进名色时若提示还在跑且仍是同一数组，**不会重头播放**（`start()` 见 `same` 就 return），四句 19.2 秒跨两段。六入两句循环到点完六点。触一句循环到段结束。受把那四句各闪一轮（每句一轮 2.4s），刚好盖住 9.6 秒。取一句闪三轮（7.2 秒）。六道只有人、畜、饿有提示；天、修罗、地狱没有。饿鬼那句按 R，对应的是 p5 粒子环的键盘，不是房屋。

改提示句改 `house-hint.js` 顶部的数组，bump `house-hint.js?v=`。改台词改 `stages.config.js` / `paths.config.js`。

## 5. 仪表与结算条不是一回事

右上角「業力計算系統」：字段含义、饼图不是判决书、假盘数字，见 [右上角仪表](./专题-右上角仪表.md)。边框是 DataV BorderBox1 的 SVG 折线移植。live 时饼心是「已过秒数」+ 下面写死 `live`。图例代码存在但主面板不调用，所以 Ether_Frictionless 这类代号观众看不到。

经文结束 show → 进「取」3 秒淡出 → 「有」一开始 `karma:finalize-start` 立刻 hide。之后观众不再看这块板。

角落进度条 `#karmaHud`：只在 Stage 10。0% 线性走到 100% 约 7 秒，文案 *Karma calculation in progress...*。走到 100% **立刻** stop 采集并 finalize，然后条淡出（约 0.4s，`karmaBarFadeMs`），换成 `index.html` 里的 *KARMIC TOPOLOGY RESOLVED* 和下面那句 dust of fate，再停约 5 秒。条的颜色从房屋点云 RGB 取样。记账窗口是前面那 7 秒，不是后面这 5 秒。

六道 HUD：`path-resolution-hud.js` 的 `show()` **每次会重写** *At this bound moment...* 和 *System loaded dedicated rules...*。只改 `index.html` 里那两句，节目里仍是脚本里的字。道名优先 `realm-assets.config.js`，logo 也是。出 HUD 时再次 hide 面板（保险）。

## 6. 终章

`final-quote-controller.js`。进段后约 2 秒才显示大字（`finalQuoteDelayMs`），按钮再晚约 1.1 秒出现，避免字和按钮抢。观众看见的终章正文在 **`app/index.html` 的 `.final-quote-text`**。分镜表 Stage 14 里也有一句同样的英文，导演进终章时会关掉底部字幕条，那一份**不会出现在屏幕上**。只改 `stages.config.js`，终章大字不变。

按钮 *Begin again* 不是整页 `reload()`：它把地址设成 `location.pathname`，**问号后面的调试参数会被丢掉**。没有「只重播六道」的接口。

所以：你用 `?market=mock` 或 `?path=egui` 测完点 Begin again，第二次会回到干净入口，去连真币安、从开场走。展场若把 mock 印进二维码，第二位观众点 Begin again 之后也会丢假盘——若网不稳，应让工作人员重新打开带 `?market=mock` 的链接，不要指望按钮替你留参数。

## 7. 改这一层时注意

- 改 HTML 结构要同步改导演里的 `getElementById`，否则层关不掉。
- 星空 video 必须 `muted`，否则很多浏览器拒绝自动播放，你会先看到黑底。
- 业力面板 `z-index` 15、不接收点击；房屋 45。六入点不着，先查是不是点偏了（命中约 42px）或拖了超过约 6px，不要先改面板。
- 自定义光标在部分 Windows 缩放比下会糊，这是跟着鼠标走的 40px canvas，不是 `cursor: url`，也不是模型问题。

## 8. 改一句提示却全场没变

提示不在分镜表里。你在 `stages.config.js` 里改字幕，底部大字变了，下面那行淡淡的英文可能还是旧的——那是 `house-hint.js`。两套字容易搞混：

- 叙事台词 = 分镜 / paths 的 `text`
- 操作说明书 = `HOUSE_LINES`、`CHU_LINES`、`QU_LINES`、`EGUI_LINES` 等

识和名色的四句提示会跨两段共用同一数组。你改第一句，两段都会变。受又把这四句各闪一轮，等于第三处复用。想只改受、不动识，要改 `house-hint.js` 里 `house-shou` 的 `start(...)` 另给数组，而不是改 `HOUSE_LINES`。

奇点那句 *Touch the central singularity...* 又不在 house-hint，而在 `index.html` 的 `#singularityHint`，由 blocking 在 4 秒后显示。三处入口，改之前先搜索英文原句属于哪一个文件。
